### Task 20.3: Periods (Part B)
- Files: `LAD/Periods.kt` (create); `LADT/PeriodsTest.kt` (create).
- Steps:
  1. `data class Period(val from: LocalDate, val to: LocalDate, val word: String, val label: String)`; `word` is the stable name (`today`, `yesterday`, `tomorrow`, `last_night`, `this_week`, `last_week`, `next_week`, `this_month`, `last_month`, `weekday:<name>`, `last_weekday:<name>`, `next_weekday:<name>`, `month:<name>`, `date:<iso>`, `days_ago:<n>`); `label` is the words used in replies ("yesterday", "last month", "on Friday 13 November", "this week"). `val singleDay: Boolean get() = from == to`.
  2. `enum class Lean { PAST, FUTURE }` and `object Periods` with:
     - `fun find(text: String, today: LocalDate, lean: Lean): Scan`, where `sealed interface Scan` is `None` (no period phrase), `One(found: Found)` or `Many` (more than one period phrase), and `Found(period: Period, rest: String, lead: String?)`: `rest` is the text with the phrase (and a lead word `on`, `for`, `in`, `during` directly before it) removed and tidied; `lead` is that lead word, or null when the phrase stood alone. `today` and `tomorrow` are period phrases like any other, so "what's on today and tomorrow" is `Many`.
       One rule for every caller in this plan: "no period phrase is present" and "the period is today" mean `None` only. `Many` is never today: a router row gets no match, a sorter result is dropped, and `SlotFill` returns null. "Finds a period" means `One` or `Many`.
     - `fun findAtEdge(text: String, today: LocalDate, lean: Lean): Found?`: the `One` case of `find`, but only when the phrase (with its optional lead word) is the first words or the last words of the text; otherwise (and for `None` and `Many`) null.
     - `fun resolve(word: String, today: LocalDate, lean: Lean): Period?` rebuilds a period from its stable `word`.
     Rules, exactly H10: weeks run Sunday to Saturday; `this_week` and `this_month` end today when `lean = PAST`; a bare weekday resolves by `lean` (PAST: the most recent one, today included; FUTURE: exactly the day `SlotParsers.scanDate` gives for a bare weekday, which counts from tomorrow, `SlotParsers.kt` near lines 29–33, so on a Friday "what's on friday" and "add task … friday" both mean next week's Friday, and today is asked for with "today"); `last <weekday>` is the one in the previous Sunday–Saturday week; `next <weekday>` resolves to exactly the day `SlotParsers.scanDate` gives for the same words (`SlotParsers.kt` near lines 41–45: counted from next Monday), so a task, an event and a question never disagree; a month name is that whole month in the current year, except: `lean = PAST` and the month is later than the current one → the previous year; `lean = FUTURE` and the month is earlier than the current one → the next year; `d/m`, `<d> <month>` and `yyyy-mm-dd`: with `lean = FUTURE` they resolve as `SlotParsers.scanDate` resolves them (it only looks forward, `SlotParsers.kt` near lines 50–82); with `lean = PAST` they resolve to the most recent such date, today included (13/11 asked on 2026-11-16 is 2026-11-13; 20/11 asked that day is 2025-11-20), and `Periods` computes that itself without `scanDate`. `last_night` is `from = to = today` and is accepted only by the sleep rows of `ask_health`; every other row treats a text with "last night" as no match. A possessive ending directly on the phrase (`friday's`, `today's`) is removed with it, so "friday's schedule" leaves `rest` = "schedule".
