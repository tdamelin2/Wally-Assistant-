## Goal
**Wally**: a private personal assistant for one person (Tim). Native apps on his Samsung S25
phone and Dell XPS 16 laptop log his day (daily check-in, spending, journal notes,
tasks, meals with AI-estimated nutrition), sync through his own HP Debian server over Tailscale, and add charts, his
calendar (from WallyCalendar) and unread email, his Garmin health data, files, goals, study
(Moodle), screentime and Spotify. A chat answers questions about his own data and makes
changes for him: plain code handles what it can, and a local AI model (on the laptop, on the
phone or on the HP) handles the rest. The HP also writes a morning briefing and a weekly report.

The app's visible name is Wally with its own icon (done in Phase 2). Internal names stay
`assistant` (server service, user, folders, `%LOCALAPPDATA%\Assistant`) and
`dev.tim.assistant` (code package) — do not rename them (D54). Future Wally apps are
not built now; `docs/plan/EXPANSION.md` says how they would plug in (D59).

## Wally brain ladder (Phases 18–19, done)
Plan: `docs/plan/wally-brain/` (SPEC.md, PLAN.md, DECISIONS.md B1–B35, RESEARCH.md).
Phase 17 showed that the HP's 2-core processor is too slow for a capable model. Every chat message
now climbs a ladder, all decided on the HP:
1. Guard checks and instant code rules for clear commands (answers in well under a second).
2. A small read-only "sorter" for reworded questions (it compares meaning using the
   `embeddinggemma` model on the HP; it never writes).
3. The laptop's model when the laptop is on.
4. The phone's own model when the laptop is off (Phase 19, 1.17.0): Gemma 4 E4B runs inside the
   S25 with no internet. It is skipped when the battery is low or power saving is on.
5. The HP's small model (`llama3.2:3b`) as a last resort; it can only fill in one fixed form.

Code never guesses: anything unclear goes on to the next step. Whichever model answers, the HP
alone saves the result. Phase 18 (1.16.0) also rebuilt the phone chat screens to match the canvas.
**Never uninstall Wally on the phone**: that deletes the 3.7 GB model file.

## Wally input handler (Phase 20 done; Phases 21–22 drafts)
Plan: `docs/plan/wally-input-handler/` (SPEC.md, PLAN.md, DECISIONS.md H1–H32).
Code does more and a model does less. Phase 20 (1.18.0): code answers questions about other days
("how much did I spend on food last month"), puts a past-day spending or meal (up to 60 days back)
on a Yes/No card that names the full date, and asks with tap buttons when a message is close to
something it can do. The composer has three buttons: Send, "Ask model" (skips the code steps) and
"Ask Codex" (the press is the approval; the answer appears in the same chat). The HP's model only
suggests in chat and never saves an add by itself (dream entries excepted). It keeps the briefing,
weekly report, chat summaries and calorie estimates. No database change in Phase 20.
Known gaps Tim accepted: a few real messages (moving an item, "everything" questions) are still
handled differently from what he meant; "Ask model" is the way round.
Tim's own exported chat messages are in `logs/real-messages/`; no agent opens that folder (H32).
The Phase 21 and 22 sections of this plan are drafts; no agent builds from them until each is
reviewed again and added to `phases.md`.

## Architecture
- `server` (HP, Debian): REST API on the Tailscale address, port 8080, bearer token per
  device. Sync (`POST /v1/sync/push`, `GET /v1/sync/pull?since=<cursor>`), `GET /v1/health`,
  `POST /v1/admin/briefing`, and since Phase 17 the chat, reminder and research endpoints.
  Polls Gmail and WallyCalendar every 15 minutes and writes the 07:00 Asia/Jerusalem briefing,
  the Sunday weekly report, chat summaries and meal nutrition estimates with its local Ollama
  model. Nightly backup at 03:00.
- Chat: the apps send every message to the HP. The HP runs the brain ladder (see above), calls
  the XPS's Ollama over Tailscale when the laptop is on, hands the turn to the phone's model when
  it is off, and is the only place a chat result is saved. The apps never call a model for chat
  themselves, except the phone running its own model when the HP asks it to.
- Calendar: events come from WallyCalendar (polled every 15 minutes); Wally no longer calls
  Google Calendar, and its Google access is Gmail only.
- `shared` (Kotlin Multiplatform library): SQLDelight schema and row mapping, sync
  engine, chart data, health mapper, the chat client with its offline send queue, reminder
  rules, and all Compose screens.
- `androidApp` and `desktopApp`: thin entry points around `shared`. Each keeps a full
  local SQLite copy, works offline, and syncs on open, after each save, every 10 min while open, every
  15 min in the background (phone), and on pull-down (last edit wins on `updatedAt`, soft deletes, `serverSeq` cursor).
  The laptop's job runner also syncs every 30 seconds while idle.
- Phone only: reads Garmin data from Health Connect on each sync, shows reminders, and holds
  the phone model (`LiteRtPhoneBrain`).
- Database upgrades: SQLDelight migration files and `PRAGMA user_version` (D56); never
  edit an existing migration, add a new one.
- Data shapes, endpoints and edge cases: `docs/plan/SPEC.md` §5–§7, and each later plan's SPEC.

## Constraints
- Windows XPS for all builds; PowerShell syntax (`;` not `&&`). The phone is reached
  with `adb` over Wi-Fi, the HP with `ssh hp` / `scp ... hp:` (key login).
- SSH rules for agents: only these commands run without asking Tim, typed exactly like
  this (no extra quotes): `powershell -ExecutionPolicy Bypass -File ops\deploy-server.ps1`,
  `ssh hp ss -tln`, `ssh hp sudo -n systemctl status assistant --no-pager`,
  `ssh hp sudo -n journalctl -u assistant -n 100 --no-pager`. Any other SSH command
  asks Tim first. Never run `sudo` on the HP without `-n` (it would wait for a password).
- Use only the versions listed under Tech stack; anything else needs Tim's approval.
- Server binds only to its Tailscale address; Ollama on the XPS only to its Tailscale
  address. No personal data leaves Tim's devices except encrypted backups in Google
  Drive, data already in Google, and Codex research questions under N28/N29.
- The HP has 8 GB RAM and 2 cores: server heap `-Xmx512m`; two models stay loaded (chat and
  sorter) but only one model answer is generated at a time.
- Money in integer agorot; instants UTC epoch ms; day fields `localDate` in
  Asia/Jerusalem.
- Nothing is saved from chat without a clear match or a tap; test pass marks are never lowered.
- No agent opens `logs/real-messages/` (H32).
- Locked decisions in `docs/plan/PLAN.md` "Locked decisions" and each plan's `DECISIONS.md`
  may change only with Tim's approval.
- graphify (code map in `graphify-out/`): before grepping or opening source files to
  find where something is, run `graphify query "<question>"` (or `graphify path "A" "B"`,
  `graphify explain "X"`), then open only the files it points to. Put this rule in every
  subagent prompt that explores code. Planning a phase: also skim
  `graphify-out/GRAPH_REPORT.md`. These commands only read. The manager runs
  `graphify update .` once after the phase's code is final (no AI calls, about a minute);
  coders, tester and debugger don't run `update`.
